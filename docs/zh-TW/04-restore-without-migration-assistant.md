# 不靠遷移輔助程式的手動還原

[English](../en/04-restore-without-migration-assistant.md) · [首頁](../../README.zh-TW.md)

**iMac17,1 #1 實測：**[v2.1 還原腳本](../../scripts/README.zh-TW.md)從加密的 Time Machine APFS sparsebundle 還原使用者。該次逐檔比對 56,605 項，沒有差異，原使用者隨後也成功登入。這只是單機結果，不代表每個 App、密鑰或系統服務都已遷移。正式寫入前，先執行 `--list` 與 `--dry-run`，核對目的系統與備份。

腳本以唯讀方式掛載映像及快照，互動設定新密碼並建立本機帳號，以 `ditto --noacl` 複製家目錄及缺少的指定 App，也可合併 `/usr/local` 下缺少的 Intel Homebrew 檔案。缺少的系統 helper 只列出，不自動安裝。Time Machine 保護 ACL 可能使還原檔案無法寫入：先前手動複製曾帶入約 35,948 項這類權限。v2.1 排除它們，並對適用的標準家目錄補回 `group:everyone deny delete` ACE。驗證會檢查殘留的 Time Machine ACE 及檔案差異。

**鑰匙圈差異實測：**新建帳號的密碼若不同於原 `login.keychain-db` 的未知舊密碼，複製舊檔也無法解鎖。最初手動複製雖然雜湊與來源一致，登入後仍一直跳密碼視窗。v2.1 把舊登入鑰匙圈另存為含日期的檔名，讓 macOS 首次登入時建立新的登入鑰匙圈。它也排除與特定 Mac 綁定的 UUID 命名「本機項目」鑰匙圈資料夾，以及 `.sb-*` 鑰匙圈檔。**原鑰匙圈中的密鑰可能不再出現在作用中的鑰匙圈**；務必保留原備份，也不要假設已開啟 iCloud 鑰匙圈。若日後找到舊密碼，可再人工從封存鑰匙圈取回。

頭貼儲存在目錄服務紀錄，不只在家目錄；腳本會在有資料時複製 JPEG。Intel Homebrew 位於家目錄外，因此須另外處理 `/usr/local`。該次實測已確認搬入的 Homebrew 樹沒有舊 UID 擁有權殘留，但 App helper、授權及登入項目仍需逐一檢查。

**與遷移輔助程式的差異：**這是選定檔案與本機帳號還原，不會搬來源密碼雜湊、Secure Token、FileVault 授權、與硬體綁定的本機項目、系統服務或所有 App 狀態。MacBookPro11,5 用遷移輔助程式成功的那次沒有相同的鑰匙圈問題，不應把該次成果歸給此腳本。v2.1 實測使用本機映像；原腳本雖有遠端複製選項，**該次沒有驗證**。

## 第二台機器的結果

**實測（iMac17,1 #2，本機映像，較新的腳本版本）：**排除綁定機器的鑰匙圈項目後，比對 56,478 個家目錄項目，內容（SHA-256）差異 0，Time Machine ACE 殘留 0，帳號頭貼與備份逐位元組相同，Homebrew 合併時沒有動到既有的 helper 連結，新帳號登入沒有跳出鑰匙圈視窗。腳本卻在最後一道檢查回報失敗：作業系統在新帳號底下自己建立了三個 `Library/Caches/com.apple.containermanagerd` 的目錄。沒有任何東西遺漏，所以這是**誤判**，較新的版本只容忍該路徑下的目錄。

**還原不會涵蓋、要手動檢查的項目：**

- **排程工作。**使用者與 root 的 `crontab` 在家目錄之外。如果 root 的排程會執行某支腳本，新機器上的那份腳本必須由 root 擁有；擁有者是舊 UID 的副本（在新機器上可能就是臨時管理員），會讓該帳號改得動 root 執行的內容。
- **Command Line Tools**、系統層級 helper（`LaunchDaemons`、`LaunchAgents`、`PrivilegedHelperTools`）與機器設定。多數 App 首次啟動時會自己重裝 helper。
- **帳號密碼。**`sysadminctl` 只問一次、沒有確認欄位，打錯字就會用錯字建帳號。執行前自己先確認輸入兩次，或在第一次登入時確認。

公開的腳本副本是較早的版本，這些缺口正在較新的版本中補上。
